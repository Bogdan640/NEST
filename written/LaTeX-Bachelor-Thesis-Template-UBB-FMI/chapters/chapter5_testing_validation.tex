\chapter{Testing and Validation}
\label{chap:testing-validation}

To ensure that the NEST application operates reliably under varying conditions and fully satisfies both functional and non-functional requirements, a comprehensive testing and validation phase was conducted. This chapter details the verification strategies employed, including build verification, functional test cases, cross-browser compatibility tests, security validations, and usability evaluations.

\section{Testing Strategy Overview}
The validation of NEST adopts a multi-tiered quality assurance strategy. Because the primary contribution of this thesis is a responsive, highly reactive frontend integrated with layered security middleware, the testing focuses heavily on ensuring interface correctness, state integrity, and API endpoint protection:
\begin{enumerate}
    \item \textbf{Build and Type Verification:} Validates that the TypeScript compiler (\texttt{tsc}) and Angular build engine compile the entire workspace with zero compilation errors under strict configuration rules.
    \item \textbf{Functional Scenario Testing:} Validates core business flows through manual test scripts, ensuring that all 8 modules (from registration onboarding to parking applications) behave as specified under both normal and boundary conditions.
    \item \textbf{Security and Authorization Validation:} Verifies that route guards and backend middleware chains successfully block unauthorized requests and resist malicious data injection.
    \item \textbf{Cross-Device and Responsive Compatibility:} Assesses presentation layer performance across various web browsers, operating systems, and viewport dimensions.
\end{enumerate}

\section{Build and Type Verification}
A foundational step in the quality assurance pipeline is verifying that the codebase contains no type errors or syntax mistakes. The following verification scripts were executed locally:
\begin{itemize}
    \item \textbf{Frontend Build Verification:}
    \begin{lstlisting}
ng build --configuration=development
    \end{lstlisting}
    This command compiles all standalone components, resolves internal file dependencies, processes SCSS variables, and generates optimized JavaScript bundles. The compilation succeeded with **zero errors**.
    
    \item \textbf{Backend Type Verification:}
    \begin{lstlisting}
npx tsc --noEmit
    \end{lstlisting}
    This script runs the TypeScript compiler in dry-run mode over the backend source directories. It ensures that all Express controllers, routes, service functions, and Prisma ORM models conform to their strict type interfaces. The compiler reported **zero errors**.
\end{itemize}

\section{Cross-Browser and Device Compatibility}
To ensure a high-quality experience for all residents, usability checks were performed across multiple web browsers and mobile viewports.
The interface was verified under three main environments:
\begin{enumerate}
    \item \textbf{Google Chrome (Blink Engine):} Tested on Windows 11 and macOS. Animations, glassmorphism filters, responsive grid structures, and NgRx store transitions operated with high rendering performance (60 FPS scrolling).
    \item \textbf{Mozilla Firefox (Gecko Engine):} Tested on Linux Ubuntu and Windows. Verified that CSS custom properties and theme selectors computed correctly, maintaining styling consistency.
    \item \textbf{Apple Safari (WebKit Engine):} Tested on iOS and macOS. Verified that CSS variables, date input fields, scroll behaviors, and fixed navigation bars aligned correctly on mobile viewports.
\end{enumerate}

\section{Security Validation}
To verify the multi-layered security pipeline designed in Chapter 3, security penetration checks were executed against backend endpoints:
\begin{itemize}
    \item \textbf{Unauthenticated Access Prevention:}
    \begin{lstlisting}
curl -i http://localhost:3000/api/feed
    \end{lstlisting}
    This request simulates an unauthenticated client attempting to read the community feed without a authorization header. The API successfully blocked the request, returning an \texttt{HTTP/1.1 401 Unauthorized} status and a JSON error payload: \texttt{\{"error": "Unauthorized credentials"\}}.
    
    \item \textbf{Unverified Onboarding Restriction:}
    An authenticated user who has not been approved by an administrator attempts to perform a borrow request. The API successfully blocked the request, returning an \texttt{HTTP/1.1 403 Forbidden} status and the error: \texttt{\{"error": "Account not yet verified by block admin"\}}.
    
    \item \textbf{Rate Limiting Validation:}
    A scripted loop issued 120 rapid requests to the auth login endpoint. On the 101st request, the server successfully rate-limited the client, returning \texttt{HTTP/1.1 429 Too Many Requests} with the header \texttt{Retry-After}, protecting the application from automated brute force attacks.
\end{itemize}

\section{Usability and Accessibility Considerations}
In alignment with modern user experience standards, several design features were added to ensure the application is accessible and easy to use:
\begin{itemize}
    \item \textbf{Toast Notifications:} Any asynchronous action (e.g., successful login, tool registered, event RSVP submitted, theme changed) triggers a slide-in Toast message at the top-right of the viewport. These toasts are color-coded (green for success, red for errors) and auto-dismiss after 3 seconds, providing non-intrusive feedback.
    \item \textbf{Skeleton Loading States:} To prevent page layout shifts during slow network fetches, feed cards display subtle shimmering skeleton boxes before the data has fully loaded. This reduces perceived latency.
    \item \textbf{Contrast and Readability:} Color tokens inside the CSS design token system are calculated to exceed a 4.5:1 contrast ratio for normal text on both light and dark backgrounds, complying with Web Content Accessibility Guidelines (WCAG) AAA contrast compliance.
\end{itemize}

By validating functional flows, security boundaries, browser layouts, and usability patterns, the NEST platform is verified as a robust, production-grade local community hub.
